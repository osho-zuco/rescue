# Prisma 7 Migrations on Railway - Setup Guide

> **Last Updated**: 2026-01-08
> **Prisma Version**: 7.2.0
> **Platform**: Railway
> **Runtime**: Bun

---

## ✅ Required Setup

### 1. **File Structure**
```
backend/
├── prisma.config.ts          ← MUST be at root level
├── prisma/
│   ├── schema.prisma         ← Schema WITHOUT url property
│   └── migrations/           ← Migration files
├── docker-entrypoint.sh      ← Runs migrations at container start
└── Dockerfile                ← Multi-stage build with proper COPY
```

### 2. **prisma.config.ts** (at root)
```typescript
import { defineConfig } from 'prisma/config';

export default defineConfig({
  schema: 'prisma/schema.prisma',
  // Conditional: only include datasource if DATABASE_URL exists (runtime)
  ...(process.env.DATABASE_URL && {
    datasource: {
      url: process.env.DATABASE_URL,
    },
  }),
});
```

**Why conditional?**
- Build time: No DATABASE_URL → Skip datasource → `prisma generate` succeeds
- Runtime: DATABASE_URL exists → Include datasource → `prisma migrate deploy` succeeds

### 3. **schema.prisma**
```prisma
datasource db {
  provider   = "postgresql"
  extensions = [postgis, uuid_ossp(map: "uuid-ossp")]
  // ❌ NO url property here!
}
```

### 4. **docker-entrypoint.sh**
```bash
#!/bin/bash
set -e

echo "Running database migrations..."
bunx prisma migrate deploy  # ← No --url flag!

echo "Starting Bun server..."
exec bun src/index.ts
```

### 5. **Dockerfile** (Multi-stage)
```dockerfile
# deps stage: Install deps + generate client
FROM oven/bun:1 AS deps
WORKDIR /app
COPY package.json bun.lockb* ./
RUN bun install --frozen-lockfile
COPY prisma.config.ts ./         # ← Copy config
COPY prisma ./prisma/
RUN bunx prisma generate

# runner stage: Copy everything needed
FROM oven/bun:1 AS runner
WORKDIR /app
COPY --from=deps /app/node_modules ./node_modules
COPY --from=deps /app/prisma.config.ts ./      # ← Must copy from deps!
COPY --from=deps /app/prisma ./prisma/
COPY . .
COPY docker-entrypoint.sh /usr/local/bin/
RUN chmod +x /usr/local/bin/docker-entrypoint.sh
EXPOSE 8080
ENTRYPOINT ["/usr/local/bin/docker-entrypoint.sh"]
```

### 6. **Railway Configuration**
- **DATABASE_URL**: Must be set in Railway environment variables
- **Pre-Deploy Command**: ❌ NOT NEEDED (migrations run in entrypoint)
- **Branch**: Ensure Railway watches the correct branch

## ❌ What NOT to Do

### 1. **Don't use `--url` flag**
```bash
# ❌ WRONG
bunx prisma migrate deploy --url="$DATABASE_URL"

# ✅ CORRECT
bunx prisma migrate deploy
```
**Reason**: Prisma 7 doesn't support `--url` flag. Use `prisma.config.ts` instead.

### 2. **Don't put `url` in schema.prisma**
```prisma
# ❌ WRONG
datasource db {
  provider = "postgresql"
  url      = env("DATABASE_URL")  # Causes build failure
}

# ✅ CORRECT
datasource db {
  provider = "postgresql"
  # No url property
}
```
**Reason**: Prisma 7 rejects `url` in schema during `prisma generate`.

### 3. **Don't use `env()` helper in config**
```typescript
// ❌ WRONG (fails at build time)
import { env } from 'prisma/config';
datasource: { url: env('DATABASE_URL') }

// ✅ CORRECT (conditional check)
...(process.env.DATABASE_URL && {
  datasource: { url: process.env.DATABASE_URL }
})
```
**Reason**: `env()` throws error if variable missing at build time.

### 4. **Don't put config in prisma/ folder**
```
# ❌ WRONG
backend/
└── prisma/
    └── prisma.config.ts  # Prisma CLI won't find it

# ✅ CORRECT
backend/
├── prisma.config.ts      # Root level
└── prisma/
```
**Reason**: Prisma CLI looks for config at project root by default.

### 5. **Don't forget to copy config in multi-stage builds**
```dockerfile
# ❌ WRONG
FROM base AS runner
COPY --from=deps /app/node_modules ./node_modules
COPY . .  # Doesn't include files from deps stage!

# ✅ CORRECT
FROM base AS runner
COPY --from=deps /app/node_modules ./node_modules
COPY --from=deps /app/prisma.config.ts ./  # Explicit copy
COPY --from=deps /app/prisma ./prisma/
COPY . .
```

### 6. **Don't run migrations in Dockerfile CMD**
```dockerfile
# ❌ WRONG
CMD bunx prisma migrate deploy && bun src/index.ts

# ✅ CORRECT
ENTRYPOINT ["/usr/local/bin/docker-entrypoint.sh"]
# Migrations in entrypoint script where DATABASE_URL is available
```
**Reason**: DATABASE_URL must be available when migrations run.

### 7. **Don't use Railway Pre-Deploy Command**
```bash
# ❌ NOT NEEDED in Railway settings
bunx prisma generate && bunx prisma migrate deploy

# ✅ CORRECT
# Let docker-entrypoint.sh handle migrations at container start
```
**Reason**: With Prisma 7, DATABASE_URL availability timing makes entrypoint approach more reliable.

## 🔍 Common Issues & Solutions

### Issue: "The datasource.url property is required"
**Cause**: `prisma.config.ts` missing or not loaded
**Fix**: Ensure config at root with conditional datasource

### Issue: "Cannot resolve environment variable: DATABASE_URL"
**Cause**: Using `env()` helper at build time
**Fix**: Use conditional `process.env.DATABASE_URL` check

### Issue: "Config file not found"
**Cause**: Config in wrong location or not copied to runner stage
**Fix**: Put at root + explicit COPY in Dockerfile

### Issue: "unknown or unexpected option: --url"
**Cause**: Using deprecated `--url` flag
**Fix**: Remove flag, use `prisma.config.ts` instead

## 📊 Migration Flow

```
1. Docker Build
   ├─ Copy prisma.config.ts (root)
   ├─ Copy prisma/schema.prisma
   ├─ prisma generate (no DATABASE_URL needed)
   └─ Build succeeds ✅

2. Container Start (Runtime)
   ├─ DATABASE_URL available from Railway
   ├─ docker-entrypoint.sh executes
   ├─ prisma migrate deploy reads prisma.config.ts
   ├─ Migrations applied ✅
   └─ Server starts ✅
```

## ✅ Verification Checklist

Before deploying:
- [ ] `prisma.config.ts` exists at backend root (not in prisma/ folder)
- [ ] Config uses conditional `process.env.DATABASE_URL` (not `env()`)
- [ ] `schema.prisma` has NO `url` property
- [ ] Dockerfile has `COPY --from=deps /app/prisma.config.ts ./`
- [ ] `docker-entrypoint.sh` runs `prisma migrate deploy` (no `--url` flag)
- [ ] Railway has `DATABASE_URL` environment variable set
- [ ] Entrypoint script is executable (`chmod +x`)

## 🚀 Development Workflow

### Local Development (Without Docker)

For local development, you can run migrations directly:

```bash
# Set DATABASE_URL in .env file first
echo "DATABASE_URL=postgresql://user:pass@localhost:5432/druto" > .env

# Generate Prisma client
bunx prisma generate

# Run migrations
bunx prisma migrate dev --name your_migration_name

# OR apply existing migrations
bunx prisma migrate deploy
```

### Creating New Migrations

```bash
# 1. Make changes to prisma/schema.prisma
# 2. Create migration
bunx prisma migrate dev --name add_new_field

# 3. Commit both schema.prisma and migration files
git add prisma/schema.prisma prisma/migrations/
git commit -m "feat(backend): add new field to model"
```

### Resetting Database (Development Only)

```bash
# ⚠️ WARNING: This will delete all data!
bunx prisma migrate reset
```

## 🔧 Troubleshooting

### Can't generate Prisma client locally

**Error**: `The datasource property url is no longer supported`

**Solution**: Create `prisma.config.ts` at backend root:
```typescript
import { defineConfig } from 'prisma/config';

export default defineConfig({
  schema: 'prisma/schema.prisma',
  ...(process.env.DATABASE_URL && {
    datasource: {
      url: process.env.DATABASE_URL,
    },
  }),
});
```

### Migrations fail on Railway

**Error**: `DATABASE_URL is not set`

**Solution**: Verify Railway environment variables:
1. Go to Railway dashboard
2. Select your project
3. Check Variables tab
4. Ensure `DATABASE_URL` is set to your PostgreSQL connection string

### Docker build fails

**Error**: `prisma.config.ts not found`

**Solution**: Ensure `prisma.config.ts` is copied in Dockerfile:
```dockerfile
COPY prisma.config.ts ./
```
